# Base Sepolia 独立测试环境

## 测试目的与入口

本环境用于验证现有 RWA 平台在公共 EVM 测试链上的部署、钱包登录、权限和稳定币交易。原有公网私链演示继续用于完整生命周期演练，其产品、账户余额和财务时间不会因为本环境的测试而改变。首页的 Launch App 仍然打开原演示，Base Sepolia 按钮打开独立公链测试入口。

Base Sepolia 的 Chain ID 为 84532，Gas 代币为测试 ETH。业务应用仍由 Mac 后端提供，链和公共区块链浏览器由外部服务提供。本环境不运行 Anvil，也不使用原演示的 RPC 隧道。应用暂时离线不影响已经写入公链的交易，用户仍可在 [Base Sepolia Blockscout](https://base-sepolia.blockscout.com) 查看记录。

## 钱包与测试资金

业主、中介、两位受托人及两位专用投资者沿用原公网角色地址。钱包中的地址不会因为切换网络而改变，但是不同链上的 ETH、USDC 和产品合约相互独立。普通钱包仍需申请投资资格并由中介批准。角色选择不会授予权限。

使用 Rabby 进入独立应用，选择角色，连接对应钱包并核对网络，然后签署登录消息。登录消息只用于建立会话，不会转移代币。之后的 USDC 授权、认购、退款和审批均需要另外确认相应交易。签名时应核对链编号、发送地址、目标合约和金额。

本环境使用 [Circle 公布的 Base Sepolia 测试 USDC](https://developers.circle.com/stablecoins/usdc-contract-addresses)，地址为 `0x036CbD53842c5426634e7929541eC2318f3dCF7e`，精度为 6 位。它不是原私链的 mUSDC，不能互相转账。测试代币没有货币价值。应用中的测试资金入口提供 [ETH 水龙头](https://portal.cdp.coinbase.com/products/faucet) 和 [Circle USDC 水龙头](https://faucet.circle.com/) 链接，应用本身不能增发 Circle USDC。领取时必须选择 Base Sepolia，到账后刷新余额。水龙头可能要求登录或限制领取频率。

## 流程与时间限制

发行流程沿用业主申请、中介估值、受托审核、业主签署、凭证铸造、业主授权、入池、资产池估值批准及募集发布。投资者取得资格后，可以在募集期内多次认购。每次追加都会使原订单审批失效，中介必须核对最新累计金额。结算前取消认购会退回该地址的全部累计认购款。

认购款先进入托管，只有订单审批、募集门槛、购买款、初始留存和有效估值等条件全部满足后，中介才可以结算并发行 DRS。10% 留存由合约自动执行，不需要另外转账。测试代币数量不足不能成为降低估值、跳过资金检查或伪造发行成功的理由。

本环境按真实区块时间运行。月度截止日、六个月转让锁定、赎回通知期和收益权到期均不能由应用提前。月度缴费需要产品已结算，并且对应服务期已经结束。中介发布账单后，业主授权并支付 Circle 测试 USDC，中介再核对业主付款与单独登记的模拟售电回款，确认净额入池。售电回款的经济来源仍为演示假设，其资金必须来自已充值的独立资金账户，不会增发 USDC。后续费用、估值审批、月度分配和领取遵循相同合约规则。

因此，本环境适合检查公共链的可运行性，不承诺在一次会议中完成五年生命周期。原公网演示保留时间推进能力，用于完整演示。Base Sepolia 页面不提供重置或推进时间按钮。

## 交易核对与数据边界

每次钱包交易确认后，可以点击交易哈希进入 Blockscout。先核对网络、状态和发送地址，再核对目标合约、方法、事件和 USDC 转移。业务页面的订单编号、证据摘要及金额应当与事件相符。钱包已提交、链上确认和浏览器索引是不同状态。浏览器索引延迟不会改变已成功执行的交易。

电站使用固定采集时间的真实记录回放。电价、费用、汇率、交付系数和未来现金流仍为明确披露的模型假设。把报告摘要写入公共链不会使预测成为实收，也不会自动验证 API 数据真实性。本次部署没有接入 Chainlink 或其他 Oracle，独立受托审核仍是现有审批机制的一部分。

## 部署与恢复

源码提供 `base:init`、`base:check`、`base:deploy`、`base:build`、`base:start`、`base:tunnel`、`base:status` 和 `base:stop`。初始化需要本机已忽略的角色配置和电站记录路径，不能在 GitHub 提交密钥。默认应用端口为 4194，Compose 项目名为 `deye-base-sepolia-test`。只运行应用服务，不启动私链或数据库。

`base:deploy` 是显式部署命令。部署意图在广播前持久化，重试使用原交易。日常启动发现部署记录缺失时会停止，不会自动花费 ETH 重建产品。业务数据和部署日志必须备份；公共链无法通过恢复本地文件撤销交易。恢复后应先核对部署地址和交易回执，再接受新的操作。不要删除部署意图文件来解决等待中的交易。

公共 RPC 可能限流或短暂不可用。系统按最多 200 个区块分页读取事件，并保存可重放缓存。请求失败时应保留原订单和交易哈希，先检查回执再重试原操作，不应再次付款。源码验证结果应以浏览器或源码核对页的实际状态为准，不能把外部 Circle 合约标为本项目部署的 MockUSDC。
