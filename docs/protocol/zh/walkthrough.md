# 访问方式与完整演示

远程测试同事从 GitHub 首页进入系统，不需要在自己的电脑安装或启动后端。本地部署部分仅供负责运行服务的人员使用。

## 同事远程测试

如果地址栏显示 `127.0.0.1:4174` 或 `localhost`，浏览器访问的是你自己的电脑，不能连接到负责人运行的测试环境。请重新打开 [GitHub 首页](https://mengzhon001.github.io/deye-rwa-demo/) 并点击 Launch App，不要使用本地部署地址。登录签名完成后，地址栏应继续保留 HTTPS 公网域名。

如果从 Rabby 的已连接网站入口打开了 `127.0.0.1`，请断开该旧网站连接，再从 GitHub 首页进入正确的应用并重新连接。无需删除钱包账户或重新导入私钥。

远程测试从 [GitHub 首页](https://mengzhon001.github.io/deye-rwa-demo/) 进入。点击 Launch App 后，浏览器跳转到演示负责人 Mac 上的 HTTPS 应用。先选择角色，再选择 Rabby 并连接、签名登录。首页和文档不需要钱包。只有当前 HTTPS 域名通过真实钱包验证后，入口才会开放；未通过时会显示具体原因，文档仍可访问。应用、RPC 和 Blockscout 均通过 Cloudflare 隧道访问。

请从 [Rabby 官网](https://rabby.io/) 安装钱包。如果同时安装 MetaMask，登录时明确选择 Rabby，系统会将请求发送给所选钱包。MetaMask 的公网入口尚未通过验证，本机演示仍保留 MetaMask 支持。

Rabby 对首次访问的低流量、未收录站点可能显示普通提示。阅读 Risk Detail，并核对负责人提供的地址。恶意站点标记不属于普通新站点提示，不应继续连接或关闭安全检测。网站不会要求输入私钥或助记词，测试账户只通过私密渠道交付。

远程场景使用独立的 Chain ID `20261008`。请使用应用提供的添加网络按钮，核对当前 RPC、Blockscout 和合约地址，不要使用本地部署部分的网络参数。HTTPS 隧道重启后地址可能变化，但普通停止和启动不会清空链或业务数据。

业主、中介和两位受托人使用维护人员分别提供的测试账户。投资者可以使用自己的测试钱包，登录后申请投资资格，再领取测试资金。不要在该网络使用真实资金。电站监控使用服务器定期获取的真实 API 读数，并显示采集时间；已签署报价继续引用其审核时保存的证据。电价、未来预测和回款均按界面说明区分。

### 直接测试投资者与重新发行

远程环境预置“光伏收益权 · 投资者体验产品”。该产品已完成协议、入池、估值审批和募集发布，尚未结算发行份额。投资者从产品大厅点击“前往认购”，领取该产品的测试资金后即可认购。负责人提供的两位专用投资者账户已完成该产品的资格审核；使用其他钱包时，仍需申请资格并由中介审批。认购无冷静期，中介可立即审核，结算前投资者可以全额退款。

原来的“发行演示 01”仍是空白草稿，管理角色可以在顶部产品选择框中切换到它，从业主申请开始。中介也可以点击“新建发行产品”，部署另一套产品合约。草稿不会出现在投资者大厅，完成受托审批并发布募集后才会显示。

每个产品有独立的测试 USDC、资格、认购和持仓。切换后应核对产品名称、合约地址和余额，并领取当前产品的测试资金。普通重置只重置选中的产品，其他产品继续保留。复用同一电站证据只是演示操作，不代表真实收益权可以重复出售。

这些产品共用测试链的财务时钟。中介推进时间会同时影响所有产品的募集截止日和估值有效期。多人测试时请先协调时间推进；电站 API 的采集时间不受影响。

维护人员在源码项目中使用 `npm run remote:start`、`npm run remote:status`、`npm run remote:stop` 和 `npm run remote:publish` 管理远程环境。Mac 必须保持开机、联网，Docker 和隧道持续运行。仅查看公开 GitHub 页面不需要运行这些命令，也不需要安装后端。

## 本地部署与访问（仅部署电脑）

```sh
npm ci
npm run web3:init
npm run web3:check
npm run web3:up
npm run web3:health
```

首页在 `http://127.0.0.1:4174/`，应用在 `/app/`，文档在 `/docs/`。Blockscout 在 `http://127.0.0.1:4000/`。MetaMask 使用 RPC `http://127.0.0.1:18545`，Chain ID 为 `20260922`，原生测试币为 DETH。不能直接双击 HTML 文件启动系统。

## 准备角色钱包

使用仅供本地测试的钱包配置。由项目维护人员配置业主、中介和两位受托地址，并向各角色提供对应的本地测试账户。不要把真实钱包助记词输入项目配置或文档。首页 Launch App 会先提示选择角色，再请求连接及签名。投资者使用普通未绑定钱包即可申请资格。

需要支付交易 Gas 和认购款时，在应用顶部领取测试资金。核对钱包可用余额，而不是认购订单金额。重置后如钱包仍显示旧 mUSDC，应通过当前应用重新添加代币。

## 完整操作顺序

1. 业主提交站点申请，中介完成资料审核并生成报价。
2. 受托人审批报价，业主接受并签署协议。
3. 中介铸造凭证，业主授权托管，中介完成入池。
4. 中介提交资产池估值，受托人批准，中介发布募集。
5. 两位投资者申请资格，中介分别审核并上链批准。
6. 投资者授权并认购，演示一位投资者取消认购并重新下单，再由中介审核各笔认购。
7. 全部订单经中介审核通过且资金满足条件后，立即结算发行，无须为认购推进时间。
8. 服务期结束后，中介在「监控与证据」发布月度账单。业主切换自己的钱包，在「资金与月度缴费」授权并支付本期 USDC 电费。中介单独登记模拟电网售电回款，核对两笔金额后确认净额入池，再计提费用、更新并审批估值和宣告月度分配。随后点击引导中的「切换到投资者」查看或领取。
9. 六个月锁定结束后，演示协商转让、偏离审核、赎回部分成交及未成交部分取消。
10. 建立服务事件，由快照投资者支持，达到门槛后两位受托人分别批准。
11. 到期后处理应收款与负债，更新最终估值，关闭产品并领取剩余现金。

每一步核对当前处理人、前置条件、钱包确认、链上结果及下一步入口。Blockscout 索引延迟时，先看回执，不要重复提交。

## 重置与维护

应用中的重置归档当前场景并部署新产品，保留电站证据和旧链上记录。停止和重新启动容器也不会删除数据卷。

```sh
npm run web3:status
npm run web3:logs
npm run web3:down
npm run web3:up
npm run web3:backup -- .data/web3-backups/demo-1
npm run web3:restore -- .data/web3-backups/demo-1 --confirm
```

`web3:clean -- --confirm` 是完全清空链与数据库的维护命令，不在业务页面提供。操作前必须先备份。

## 自动化验证

`npm run web3:e2e` 会先备份当前环境，运行完整钱包与五年业务闭环，并在结束时恢复原数据。执行期间应停止人工业务操作。测试资金与合成样本不应留在真实 API 演示场景中。
