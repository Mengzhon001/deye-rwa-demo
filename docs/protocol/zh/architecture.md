# 架构、接口与交易恢复

本地环境使用 Anvil 私链、过滤后的 RPC 网关、Blockscout、后端及前端。Hardhat 负责编译和测试。首页、文档和应用通过同一 HTTP 服务发布，站点静态内容不依赖钱包或 RPC 成功响应。

## 四类状态

API 观测、估值模型、后端审核和链上确认分别记录。资料审核成功不等于链上交易成功，钱包提交不等于交易已确认，Blockscout 索引状态也不决定交易是否成功。

## 主要 HTTP 接口

| 接口 | 用途 |
| --- | --- |
| GET /api/network | 提供链 ID、钱包 RPC、浏览器地址和公开角色配置。 |
| GET /api/public/overview | 返回经过筛选的站点与产品数量、来源及可用性，不返回原始业务状态。 |
| GET /api/public/deployment | 返回当前部署地址、交易及源码构建匹配结果。 |
| GET /api/products?status=current | 登录后查询当前已发布产品。history 查询失败或关闭产品，草稿始终排除。 |
| POST /api/auth/challenge | 提交 address 与 requestedRole，获得绑定角色的一次性签名挑战。 |
| POST /api/auth/verify | 提交 nonce 与 signature，验证成功后写入 HttpOnly 会话。 |
| GET /api/session/current | 查询当前会话，不代替钱包账户与链 ID 核对。 |
| POST /api/auth/logout | 清除会话。 |
| GET /api/state | 登录后读取当前业务、观测及链上状态。 |
| POST /api/actions | 执行业務操作，按角色和幂等键校验。 |
| POST /api/wallet/prepare | 持久化交易意图并返回需要钱包签署的交易。 |
| POST /api/wallet/submitted / confirm / reject | 登记提交、核对回执或记录拒签。 |
| POST /api/faucet | 为当前钱包领取明确标记的测试资金。 |

钱包模式下，业务写入要求签名会话及同源 JSON 请求。请求绑定 expectedVault，避免重置后误用旧场景。公开接口不包含 AppSecret、登录凭据、原始签名交易或审核文件。

## 交易恢复

后端在钱包签名前保存操作意图，按顺序执行操作。回执确认时核对发送人、链、目标合约、方法、参数、金额和预期事件。只有交易哈希不足以证明业务完成。

刷新后从持久化意图、回执和合约状态恢复。拒签保留可解释状态；失败交易不会推进流程。交易等待、替换或索引延迟需要查看当前交易日志，不能重复创建新付款来掩盖旧交易。

## RPC 边界

钱包使用端口 18545 的网关。网关允许查询和广播已签名交易，禁止节点代签、账户冒充、修改余额、重置链和任意推进时间。内部 Anvil 节点不能直接对外公开。财务时间推进仅供受控演示，不产生真实电站数据。


## 月度账单与资金流

中介发布账单后，业主授权并向 HouseholdBilling 支付本期测试 USDC。售电回款由独立系统账户单独登记。两笔资金先保存在账单合约中；中介核对后签署确认交易，合约一次性处理站点成本和净额入池。后端分别保留账单、业主付款、售电回款和确认入池交易，不将应收款与现金重复计算。重启时从账单合约事件和状态恢复付款记录，旧账期的已确认回款不会重新收费。
