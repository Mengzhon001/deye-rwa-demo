# Base Sepolia 独立部署验证记录

验证日期为 2026 年 10 月 29 日。本次从独立源码分支构建 `deye-base-sepolia-test` 应用，使用 Chain ID 84532 和 Circle 官方测试 USDC。原公网私链仍为 20261008。两套环境沿用六个角色地址，但使用不同合约和业务存储。

## 公链结果

电站凭证、RevenueShareVaultV5 和 HouseholdBilling 已部署到 Base Sepolia。三份合约在 Sourcify 上均为 `exact_match`，Blockscout 随后也确认源码验证成功。Circle USDC 是外部合约，不作为本项目部署源码进行匹配。

真实公链流程覆盖业主申请、中介审核与估值、受托审核、业主接受及协议消息签署、电站凭证铸造、业主授权、收益权入池、资产池估值提交与批准、募集发布，以及两位投资者的资格申请和审批。两位投资者分别完成 1 USDC 首次认购、2 USDC 追加、订单审核和全额退款。追加之后，原审核确实失效，最新累计金额需要重新批准。

使用真实 Rabby 0.94.11 和六套隔离 Chromium 配置，在独立 HTTPS 地址完成六个角色账户的消息签名登录。所有浏览器均在隐藏模式运行。投资者另外通过实际页面和 Rabby 完成拒签、重试、USDC 授权、认购、页面刷新与退款。拒签后，原输入金额得到保留。测试中的额外托管款均已退回。

最终核对了 31 项成功业务操作，其中 23 项包含链上交易，8 项为明确区分的链下操作。30 笔业务交易的发送者、Chain ID、目标、调用参数、回执、预期事件及相关 USDC 转移均与持久化操作意图相符。完整的公开核对结果保存在 `base-sepolia-transactions-2026-10-29.json`，不包含私钥、消息签名、原始证据或 API 凭证。

交付时，独立产品处于募集中。累计托管认购为零，DRS 总供给为零，两位专用投资者各持有 20 Circle 测试 USDC，并保有足够支付本次规模交易的测试 ETH。角色地址和其他测试账户的资金已准备好。

## 修复与回归

实际公链测试暴露了钱包广播与后端 RPC 可见性之间的延迟。系统现在会在限定范围内重试原哈希的登记，浏览器会在登记前保存已广播哈希。原电站铸造交易在恢复后完成核对，没有重复铸造。

公共 RPC 的每秒 25 次请求限制和单次 200 区块日志限制也经过实际验证。当前版本使用只读 Multicall3 聚合、请求节流、有限重试和可恢复事件缓存。Multicall3 只用于 `eth_call`，不会代签或持有本系统的资金。拒签后的表单刷新曾改变认购默认值，现已修复并由真实钱包重试验证。测试资金窗口的布局和代币标识也已检查。

收益模型与数据测试通过 27 项，收益权合约专项测试通过 15 项。全部合约测试通过 31 项，原有可选分叉测试因未启用该模式而跳过一项。界面流程通过 38 项，引导通过 29 项，新增 RPC、网络策略和事件缓存测试通过 3 项。四角色本地回归继续覆盖结算、九个月运营、分配领取、原子转让、部分赎回、两名受托人和重启恢复。前后端类型检查及站点构建通过。

## 原演示保护与实际边界

原公网五份运行配置的摘要、容器 ID、场景标识、合约地址、凭证入池数量和份额供应量均与实施前一致。没有重启原演示容器或隧道，也没有重置其业务数据。GitHub 首页增加了单独的 Base Sepolia 按钮，原 Launch App 和 `remote.json` 继续指向原演示。

本次没有在公共链完成足额募集结算，也没有提前演示月度缴费、分配、六个月转让锁、赎回和到期关闭。这些操作仍受真实资金和区块日期约束，完整生命周期仅在本地回归和原私链演示中执行。HouseholdBilling 已部署并核对其 USDC、资产池和角色绑定，月度付款在 Base Sepolia 上的正向执行仍需等待实际结算与服务期到期。

电站使用固定记录回放，电价及未来现金流属于披露的模型假设。本次未接入 Oracle。真实扩展测试使用 Rabby，没有宣称新 HTTPS 地址已通过 MetaMask 的安全分类或实际扩展测试。Mac 业务服务和隧道需要保持运行；Base Sepolia 和公共浏览器不会因本机停止而被清除。
