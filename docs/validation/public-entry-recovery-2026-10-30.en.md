# Public entry recovery validation

On 30 October 2026, the previous unified application hostname stopped resolving. The Mac's gateway, private-chain application and Base Sepolia application remained accessible locally. Although the old Cloudflare process was alive, it repeatedly logged `Unauthorized: Tunnel not found`. Process existence therefore did not establish public availability. The old private-chain RPC and explorer hostnames also failed to resolve.

Recovery recreated tunnels for the same approved ports, updated origin allowlists and reloaded the applications and private explorer frontend. Anvil and the databases were not restarted, data volumes were not cleared, and no contracts were redeployed. GitHub Pages configuration now points to the recovered entry. Bilingual online documentation directs readers through the stable GitHub homepage to obtain the current application address.

The recovered application is `https://reuters-romance-arranged-bloggers.trycloudflare.com`. Base Sepolia uses `/networks/base-sepolia/app/`, and the private demonstration uses `/networks/private/app/`. The private RPC is `https://mazda-lopez-stevens-pittsburgh.trycloudflare.com`, and its explorer is `https://quizzes-faces-simplified-discuss.trycloudflare.com`. These remain temporary addresses and may change. Base Sepolia's wallet RPC remains `https://sepolia.base.org`, and its public Blockscout explorer is unchanged.

Login validation exposed another delay: historical event catch-up after the overnight gap. The original endpoint permits at most 200 blocks per log query, making a large catch-up exceed the browser's loading deadline. An optional read-only history RPC now supports larger pages. This instance uses `https://base-sepolia.gateway.tenderly.co` with pages of up to 50000 blocks. Startup checks the Chain ID. Collection compares the historical boundary hash with the primary RPC, reads the latest twelve blocks through the primary RPC, and commits the cache cursor only after all pages and timestamps succeed. A chain mismatch or failed read cannot be reported as complete history. Wallet broadcasts and current contract reads retain the original RPC.

The status command now requests the actual public network descriptor rather than reporting success solely from a surviving process. The tunnel command can replace an unreachable connector after checking process ownership. It publishes the new configuration only after the endpoint passes its network-descriptor check. This is an operator command; no scheduled monitor was added.

Post-recovery checks covered signed authentication and workspace reads for all six test accounts on both chains, wrong-role rejection, chain-specific sessions, the restricted RPC and private Blockscout. The real Rabby 0.94.11 extension entered the Base Sepolia workspace in a hidden browser and displayed three subscription guide tips without submitting a subscription. Both deployments retained the same contract addresses and deployment transactions, and every previously cached event was preserved. Eight RPC/history checks, two public-health/gateway checks and TypeScript validation passed.

No business transaction was submitted, financial time was not advanced, and a complete lifecycle was not repeated. The bilingual PDF manuals remain the 29 October editions; obtain current temporary endpoints from the GitHub homepage. Raw results and screenshots remain locally in `.data/unified-app/validation/recovery-2026-10-30/` and adjacent validation directories. Wallet keys were not published.
