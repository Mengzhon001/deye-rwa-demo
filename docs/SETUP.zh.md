# 安装、钱包与数据源配置

## 环境准备

使用 Node.js 22.19 或更高的 22.x 版本。根目录的 `.nvmrc` 提供了参考版本，根目录的 `package-lock.json` 固定依赖。请在仓库根目录运行 `npm ci`，不要分别在三个工作区执行 `npm install`。

完整服务需要 Docker 和 Docker Compose。当前脚本使用 `docker-compose` 命令。如果你的安装仅提供 `docker compose`，需要安装兼容命令或将脚本中的调用改为对应形式。Blockscout 的首次拉取、数据库迁移和合约验证依赖下载可能需要数分钟。

默认应用、浏览器和 RPC 分别使用本机的 4174、4000 和 18545 端口。启动前应确认这些端口没有被其他演示环境占用。本源码的 Compose 项目名为 `deye-rwa-platform`，它的卷与原工作目录的本地演示项目分开。

## 安装与启动

```sh
npm ci
DEYE_LOCAL_SOLC=1 npm run build
npm run web3:init
npm run web3:wallets
npm run web3:up
npm run web3:health
```

`web3:init` 只在配置不存在时生成 `.env.web3.local`，并从 `.env.example` 建立 `.env.revenue`。前者包含本地节点助记词、角色地址和随机生成的数据库及浏览器密钥。后者用于配置电站接口和数据源。两个文件都被 Git 忽略。重复初始化不会更换已经生成的钱包。

`web3:up` 构建应用镜像并启动服务。后端连接节点后部署本场景需要的合约，持久化部署记录，并按配置向 Blockscout 提交源码验证。请先等待 `web3:health` 通过，再连接钱包。该命令检查服务可用性，具体合约是否已验证仍应在浏览器中确认。

Apple Silicon 是现有完整环境的主要运行平台。初始化根据宿主机选择 `linux/arm64` 或 `linux/amd64`，并写入 `DEYE_DOCKER_PLATFORM`。源码验证服务始终使用 amd64 编译器，在 Apple Silicon 上需要 Docker 的 x86 模拟支持。其他平台的镜像拉取和完整服务启动应在目标机器上重新验证。

## 测试钱包

`npm run web3:wallets` 将六个业务测试账户写入 `.data/local-wallets/wallet-import.private.json`，文件权限为 600。终端只显示角色及地址，不显示私钥。用本机编辑器打开这个文件，分别把需要的账户导入 Rabby 或 MetaMask，并自行命名为业主、中介、投资者 A、投资者 B、受托人 A 和受托人 B。

不要将该文件提交到仓库。它只适用于此本地演示链，也不包含原演示环境的账户。如果需要共同测试已经运行的远程环境，应另外取得那套环境的业务测试账户。自行初始化的账户不会自动拥有远程环境的角色权限。

访问 `/app/` 后先选择角色，再连接相应钱包并签名。应用会提示添加或切换网络。Chain ID 为 `20260922`，RPC 为 `http://127.0.0.1:18545`，浏览器为 `http://127.0.0.1:4000`。签名消息用于登录，不是转账。后续业务交易另行请求钱包确认。

中介与两位受托人必须使用不同地址。受托人 A 和 B 分别审批涉及收款方变更的处置，两份独立批准用于演示职责分离。普通投资者还需要申请资格，并由中介批准后才能认购。余额不足时使用应用中的测试资金领取入口。

## 数据源

初始业务场景没有电站。登录中介工作台后，在数据源设置中明确选择合成样本，可先演练业务。合成样本会在界面标注，不能用作真实资产的估值证据。

实时接入需要自行在 `.env.revenue` 填写 `DEYE_REGION`、`DEYE_APP_ID`、`DEYE_APP_SECRET`、`DEYE_EMAIL`、`DEYE_PASSWORD`，并按需要设置公司上下文。将 `REVENUE_AUTO_SYNC_STATION_ID` 设置为自己有权访问的电站编号后，重建应用服务以应用配置。不要把凭证放入前端代码。

电量和功率字段的名称、单位、时区及导出电量语义必须经过实际核对。只有完成核对后才能设置 `DEYE_MAPPING_VERIFIED=true`，并填写 `DEYE_MAPPING_NOTE`。读取成功不等于估值输入已得到验证。电价、费用、汇率和未来预测属于单独的模型假设。

记录回放需要一份通过验证的采集文件。本仓库没有附带客户原始记录。容器模式下应另外为采集文件增加只读挂载，并将 `DEYE_REPLAY_FILE` 指向容器内路径；需要首次自动加载时，再设置 `REVENUE_INITIAL_REPLAY=true`。不能只填写宿主机路径而不挂载文件。

## 第一轮业务操作

从空白场景开始，业主选择电站并提交申请。中介在申请列表审核资料，形成报价和估值。受托人审批后，由业主接受并签署协议。随后中介铸造电站凭证，业主授权托管，中介执行入池。

中介提交资产池估值，受托人批准后，中介发布产品。投资者在产品大厅选择产品，申请资格，领取测试资金，授权 USDC 并认购。当前演示版本采用中介审核认购订单后结算的方式，不要求三天冷静期。只有结算成功后才发行投资者份额。

后续运营包括月度账单、明确标注的模拟回款、费用、季度分配和领取，以及锁定期后的转让与赎回。完整规则见 `docs/protocol/zh/` 中的业务文档，也可以在网站 `/docs/` 阅读。财务时间推进只用于演示，不改变 API 数据的采集时间。

## 停止与恢复

```sh
npm run web3:status
npm run web3:down
npm run web3:up
```

普通停止保留数据卷、链上记录和业务状态。业务页面中的重置会建立新的产品场景，保留旧交易。`npm run web3:clean -- --confirm` 则删除本 Compose 项目的数据卷，仅在确实需要完全重建时使用。

备份使用 `npm run web3:backup -- .data/backups/my-backup`，恢复使用 `npm run web3:restore -- .data/backups/my-backup --confirm`。备份会暂时停止服务，并包含钱包、业务数据等敏感运行信息，因此应单独保存，不纳入源码共享。

## 月度 USDC 缴费

新部署默认包含 `HouseholdBilling`。对已有产品启用 `REVENUE_HOUSEHOLD_PAYMENTS_ENABLED=true` 后，服务启动会安装与该产品及角色绑定的缴费合约，不重置产品，也不会向已收款的旧账期补收电费。远程运行工具已开启此配置。运维升级前应备份应用数据、节点状态和浏览器数据库。

中介在「监控与证据」发布月度账单，业主在「资金与月度缴费」核对金额，先授权测试 USDC，再确认缴费。中介单独登记电网售电的模拟到账，核对两笔资金后点击「核对并确认收款入池」。业主的缴费不能由售电模拟款替代。收款后仍需按月计提费用、编制并审批净值，然后宣告分配，最后由投资者领取。网页会显示各自的交易链接。

已有未收款账单可以显式发布为钱包缴费账单。已结清账期保持原记录。钱包拒签、余额不足或交易失败不会把账单标为已支付，重复付款会被合约拦截。
